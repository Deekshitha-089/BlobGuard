What is a file version?

When blob versioning is enabled, Azure can preserve an earlier version when a blob is overwritten. This means an accidental change does not necessarily mean the original content is lost.

✓

Azure protection overview

BlobGuard uses Azure Blob Storage's built-in protection features. The descriptions below explain their roles.

◷

Blob versioning

Enabled

Automatically preserves previous blob versions when supported changes occur. Each version can contain different file content.

Why it matters: Helps recover an earlier copy after an accidental overwrite.
↻

Blob soft delete

31 days

Retains deleted blobs during the configured 31-day retention period instead of immediately removing them permanently.

Why it matters: Gives you time to recover a blob deleted by mistake.
▤

Container soft delete

31 days

Retains deleted containers for the configured retention period, helping recover a container and its contents.

Why it matters: Helps protect against accidental deletion of an entire container.
≡

Azure Change Feed

Enabled

Records changes made to blobs, including supported create, update and delete operations.

Why it matters: Helps investigate when data changes and understand storage activity.
⏱

Point-in-time restore

30-day target

Supports restoring eligible block blobs to an earlier time within the configured restore window.

Why it matters: Helps recover from accidental or unwanted changes affecting multiple supported blobs.
▥

Lifecycle management

60-day rule

The configured lifecycle rule manages older blob versions and deletes versions that meet the 60-day age condition.

Why it matters: Helps manage storage growth and the cost of retaining older versions.
ⓘ

These are the Azure settings configured for the BlobGuard project. Live status verification and configuration management from this dashboard will be connected through the Azure integration.
